# Техническое задание (ТЗ)
## Разработка экспериментального терминального стенд-бота «LatentHalt-CLI»

---

### 1. Назначение и цели проекта

Наименование проекта `LatentHalt-CLI` (Research Verification Terminal Bot).  
Основная цель Создание минималистичного, прозрачного исследовательского инструмента (Proof-of-Concept) для верификации теории преодоления вычислительной симметрии LLM в режиме живого диалога.
Текст статьи: https://github.com/vasiliypavlov/latent-halt


Ключевые исследовательские задачи, решаемые ботом
1. Интерактивная демонстрация «Акта Остановки» (прерывание вычислений на 18-м слое при распознавании детерминированных алгоритмических задач).
2. Замер когнитивного трения ($Delta_{text{friction}}$) на свободных диалоговых и логически сложных контекстах в реальном времени.
3. Мгновенное AB-тестирование гипотезы через сопоставление стандартного авторегрессионного режима и метода `LatentHalt` на одном и том же запросе.

### 2. Базовые принципы и ограничения разработки

1. Читаемость кода важнее микрооптимизации  
   Код пишется как открытая научная иллюстрация к статье `latent-halt-ru.md`. Вся математика тензоров (Logit Lens, софтмакс, энтропия, дельта векторов) должна быть написана явно и прозрачно на стандартном PyTorch, без низкоуровневых скрытых хаков на C++CUDA и без сторонних фреймворков-комбайнов (никаких vLLM, Ollama, LangChain).
2. Нулевой веб-интерфейс  
   Интерфейс строго ограничен терминалом (CLI). Допускается использование библиотеки `rich` исключительно для отрисовки аккуратных ASCIIUnicode-таблиц телеметрии и разделителей.
3. Монолитная среда  
   Скрипт должен представлять собой один автономный Python-файл (например, `chat_terminal.py`), запускаемый в том же виртуальном окружении, где проводились базовые тесты (`torch`, `transformers`, `accelerate`).
4. Целевая аппаратная платформа и модель  
    GPU NVIDIA GeForce RTX 3070 Laptop (8GB VRAM)  CUDA.
    Модель `QwenQwen2.5-1.5B-Instruct` (FP16).

### 3. Функциональные требования

#### 3.1. Архитектура CLI и парсер инлайн-флагов
Бот работает в бесконечном интерактивном цикле ввода (`User `).  
Входная строка пользователя анализируется до передачи в токенизатор парсер отделяет содержательную часть промта от управляющих флагов на конце строки.

Спецификация флагов
 `--latent` (или `-l`) Режим LatentHalt (активен по умолчанию, если флаги не указаны). Включает суб-токенное зондирование на 18-м слое.
 `--standard` (или `-s`) Принудительный стандартный режим (полный авторегрессионный прогон через все 28 слоев).
 `--both` (или `-b`) Режим AB-тестирования. Выполняет оба прогона последовательно и выводит сравнительную карточку эффективности.
 `--verbose` (или `-v`) Режим подробной послойной томографии (выводит траекторию концепта $L_{16} to L_{20} to L_{24} to L_{28}$).

Служебные команды сессии
 `clear` Очистка контекста истории диалога.
 `stats` Вывод интегральной статистики сессии (суммарно сэкономленные слое-проходы и среднее ускорение).
 `exit` (или `quit`) Корректное завершение работы.

#### 3.2. Режим 1 Стандартный инференс (Baseline)
1. Промт оборачивается в нативный диалоговый шаблон модели `tokenizer.apply_chat_template(messages, tokenize=False)`. Это исключает «синдром школьной тетради» в обычном диалоге.
2. Вызывается штатный метод `model.generate()` с жадным декодированием (`do_sample=False`).
3. Фиксируются метрики
    Время генерации ($T_{text{std}}$, мс).
    Количество сгенерированных токенов ($N_{text{tokens}}$).
    Затраченные слое-проходы $text{Passes}_{text{std}} = N_{text{tokens}} times 28$.

#### 3.3. Режим 2 Суб-токенный перехват (LatentHalt Mode)
1. На этапе нулевого шага генерации входной контекст прогоняется через модель с извлечением промежуточных скрытых состояний (`output_hidden_states=True`).
2. Контрольный рубеж На слое 18 (относительная глубина $approx 64%$) извлекается вектор $h_{18}$ последнего токена.
3. Рассчитывается вектор логитов $mathbf{z}_{18} = W_U cdot text{RMSNorm}(h_{18})$ и энтропия $H(mathbf{z}_{18})$.
4. Детектор алгоритмического синтаксиса
    Проверяется наличие явных арифметических операторов в запросе (регулярное выражение `d+s[+-]sd+`).
5. Ветвление логики
    Случай А (Сработал перехватчик)  
     Активируется Акт Остановки. Прогон слоев 19–28 блокируется. Числа передаются в CPU-парсер (модуль `math`  `operator`). Генерируется ответ.  
     Затраты фиксируются как $text{Passes}_{text{latent}} = 18$.
    Случай Б (Свободный контекст  Гуманитарный диалог)  
     Перехватчик не активируется. Модель завершает генерацию через все 28 слоев.  
     Одновременно с этим извлекается вектор $h_{28}$, рассчитываются логиты $mathbf{z}_{28}$ и вычисляется Индекс когнитивного трения ($Delta_{text{friction}}$) между слоями 18 и 28.

#### 3.4. Логика режима `--both` и управление историей (Context Hygiene)
При вызове флага `--both`
1. Запрос прогоняется через Стандартный режим $to$ фиксируется результат и метрики.
2. Запрос прогоняется через Режим LatentHalt $to$ фиксируется результат и метрики.
3. В терминал последовательно выводятся оба ответа и сравнительная таблица.
4. Правило коммита в историю Чтобы контекст диалога не засорялся возможными галлюцинациями стандартного режима на математике, в долговременную память беседы (`messages`) сохраняется валидный ответ (результат перехватчика `LatentHalt`, если задача была счетной, либо согласованный ответ 28-го слоя для обычного текста).

### 4. Алгоритмический и математический аппарат

В скрипте должны быть явно реализованы в виде отдельных чистых функций следующие формулы из статьи

1. Информационная энтропия Шеннона (в битах)
   $$P(x_i) = text{Softmax}(mathbf{z})$$
   $$H(mathbf{z}) = -sum_{i=1}^{V} P(x_i) log_2 P(x_i)$$

2. Геометрическое расхождение представлений (Косинусное расстояние)
   $$Delta_{text{geom}} = 1 - frac{h_{18} cdot h_{28}}{h_{18} h_{28}}$$

3. Симметричная дивергенция Йенсена–Шеннона
   $$M = frac{1}{2}(P_{18} + P_{28})$$
   $$Delta_{text{info}} = D_{JS}(P_{18} parallel P_{28}) = frac{1}{2} D_{KL}(P_{18} parallel M) + frac{1}{2} D_{KL}(P_{28} parallel M)$$

4. Интегральный индекс когнитивного трения
   $$Delta_{text{friction}} = Delta_{text{geom}} times Delta_{text{info}}$$

### 6. Структура проекта и исходного файла

Проект оформляется как один модуль в корне репозитория
`Elatent-haltchat_terminal.py`

Внутренняя модульная структура скрипта
1. `Config & Device Init` Загрузка модели в FP16 на CUDA, инициализация констант (слой 18, 28).
2. `Math Utilities` Функции расчета энтропии, JSD и когнитивного трения на PyTorch.
3. `Prompt & Flag Parser` Разбор инлайн-флагов (`--both`, `--latent`, `--standard`, `-v`).
4. `Inference Engines`
    `run_standard_generation()`
    `run_latent_halt_inference()`
5. `Interactive Session Loop` Цикл `while True`, хранение списка сообщений `messages`, форматирование телеметрии в консоли.

### 7. Критерии приемки

1. Работоспособность на одном GPU Скрипт стабильно запускается и не вылетает по памяти (OOM) на RTX 3070 Laptop (8GB VRAM).
2. Корректность перехвата На запросах со сложением, умножением, делением и вычитанием в режиме `--latent` модель тратит строго 18 слоев и возвращает точный ответ без галлюцинаций.
3. Корректность диалога В обычном общении бот поддерживает связный многопользовательский контекст (помнит предыдущие реплики), корректно рассчитывая $Delta_{text{friction}}$.
4. Чистота зависимостей Для работы требуются только `torch`, `transformers` и стандартная библиотека Python (опционально `rich` для таблиц). Код полностью документирован и читается как прямое продолжение статьи.

Рализуй два уровня:

| Уровень реализации | Оценка сложности | Время разработки | Что под капотом |
| :--- | :---: | :---: | :--- |
| **Уровень 1: Нейро-символический терминальный бот (PoC)** | **Низкая (3/10)** | 1–2 вечера (~200–300 строк кода) | Стандартный `transformers` + `torch` + CLI (`rich`). Переключение режимов командой `/mode`. Перехват задач на слое 18 + классический `prefill`. |
| **Уровень 2: Диалоговый бот с замером $\Delta_{\text{friction}}$ и каскадом** | **Средняя (5/10)** | 3–5 дней | Добавляется хранение истории диалога (Chat Template), расчет когнитивного трения на лету, вывод телеметрии (сэкономленные FLOPs). |
| **Уровень 3: Токен-за-токеном Early Exit для всего текста** | **Высокая (8/10)** | 2–3 недели | Требует глубокого вмешательства в KV-кэш верхних слоев (проблема дыр в памяти), что на чистом Python без C++ движков будет работать медленно. |

**Вывод:** Нам нужен **Уровень 1 + 2**. Это дает мгновенный вау-эффект, не ломает KV-кэш и наглядно демонстрирует обе концепции из статьи: **мгновенный Акт Остановки** на детерминированных задачах и **замер когнитивного трения** на сложных диалоговых ветках.
